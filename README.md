# HealthWatch — Multi-Disease Surveillance & Early Warning System (with municipality-wide EHR)

A full-stack web application for **community-level, multi-disease surveillance, trend monitoring, and rule-based early warning** for the **Municipality of Lopez, Quezon** — now backed by a **municipality-wide Electronic Health Record (EHR)**.

The EHR is the cross-facility, patient-centric source of truth; the surveillance layer reads a **de-identified** view of it. When a clinician at any facility records a **confirmed, notifiable** diagnosis during an encounter, the system automatically generates an anonymous surveillance `Case` that feeds the existing early-warning engine.

The EHR adds: a **facility / provider registry**, a **cross-facility patient index** (ISO/TS 22220 identifiers), **inter-facility referrals** (ISO 13940), **standardized terminologies** (ICD-10, LOINC, SNOMED), **HL7 FHIR R4** export + **International Patient Summary**, a **consent-governed Health Information Exchange** (ISO 22600), security/audit aligned to **ISO 27799 / RA 10173**, and a **patient portal**. See [docs/EHR_CONFORMANCE.md](docs/EHR_CONFORMANCE.md) for the full standards/conformance matrix and FHIR + PHIE/PhilHealth Konsulta mappings.

## ⚠️ Important Disclaimer

**This system is NOT a medical diagnostic decision tool.** It is an EMR plus a risk-based surveillance and early warning platform for Rural Health Units (RHU) and Barangay Health Workers (BHW). It supports:

- Patient-centric electronic medical records (encounters, vitals, diagnoses, prescriptions, immunization, maternal/prenatal, labs)
- Centralized, multi-disease case reporting (manual + auto-generated from encounters)
- Trend monitoring and analysis per disease
- Environmental / transmission-risk factor tracking
- Rule-based early warning alerts

Patient records contain personal information and are handled under the **Data Privacy Act of 2012 (RA 10173)**: explicit patient consent is required before encounters can be recorded, access is restricted to clinical roles, and all access is audited.

The early-warning engine uses **configurable rule-based logic, NOT AI/ML**. The forecast view uses **simple linear regression** (basic statistics) for short-term projection — clearly labeled as such.

## 🎯 Features

### Disease Registry (configurable)
The RHU admin manages the list of tracked diseases. Each disease has:
- A transmission category (vector-borne, water-borne, airborne, direct-contact, other)
- A monthly case threshold and spike-percentage threshold (drives alerts)
- Seasonal transmission months
- Notifiable (PIDSR) flag and active/inactive status

Pre-seeded with PIDSR-style diseases: Dengue, Malaria, Typhoid Fever, Acute Bloody Diarrhea, Leptospirosis, Influenza-like Illness, Measles, Tuberculosis, and COVID-19.

### Electronic Medical Record (EMR)
Patient-centric clinical records for the RHU:
- **Patient registry (Master Patient Index)** — demographics, barangay, PhilHealth no., blood type, unique patient code, and Data Privacy Act consent.
- **Encounters / visits** — SOAP notes (Subjective, Objective, Assessment, Plan), encounter type (Consult/Prenatal/Immunization/TB/NCD/Follow-up), and chief complaint.
- **Vital signs** — BP, temperature, HR, RR, weight, height, auto-computed BMI, SpO₂.
- **Diagnoses** — ICD-10 reference, certainty, primary flag; a confirmed notifiable diagnosis auto-generates a de-identified surveillance case.
- **Prescriptions** — multi-item medication orders (drug, dose, frequency, duration, instructions).
- **Allergies & problem list**, **immunization (EPI)**, **maternal / prenatal**, and **laboratory results**.

### Case Management (multi-disease)
Create/read/update/delete cases linked to a disease and barangay. Tracks status (Suspected/Probable/Confirmed), outcome (Ongoing/Recovered/Died), age, sex, source, and onset date. Cases can be entered manually or auto-generated from EMR encounters (flagged via `autoGenerated`).

### Environmental Risk Reports (by category)
Risk factors grouped by transmission category:
- **Vector-borne:** stagnant water, poor waste disposal, clogged drainage, housing congestion
- **Water-borne:** unsafe water source, poor sanitation, open defecation, food contamination
- **Airborne:** overcrowding, poor ventilation, active respiratory case nearby

### Dashboard & Analytics
Per-disease and overall stats, monthly trends, disease breakdown, barangay rankings, and a rule-based 3-month projection.

### Early Warning (rule-based)
For each active disease and barangay, the engine compares current vs. previous month case counts, factors in the disease's seasonal months and matching environmental risk reports, and classifies risk as **LOW / MEDIUM / HIGH** against the disease's own configurable thresholds. Alerts are created, updated, or auto-resolved accordingly.

### Reports & Exports
Cases, risk reports, and a monthly summary, exportable as CSV or Excel (XLSX), with optional disease/date filters.

## 👥 User Roles

1. **Admin (RHU)** — full access: manage users, facilities, diseases, barangays; full EHR access; view all dashboards; export.
2. **Health Officer (MHO)** — municipality-wide reach across all facilities; manages facilities; full clinical + surveillance access.
3. **Facility Admin** — administers a single facility.
4. **Physician / Nurse / Midwife (clinical roles)** — full access to patient EHR (registry, encounters, programs, referrals, consent, HIE). Patient PII is restricted to these roles + Admin/MHO/Facility Admin.
5. **Barangay Health Worker (BHW)** — encode cases and risk reports for their assigned barangay; view alerts; export. No access to patient PII.
6. **Hospital Encoder** — submit case reports.
7. **Resident** — patient portal: view own record, manage sharing consent; submit risk reports; view public advisories.

## 🚀 Setup

### Prerequisites
- Node.js 20 LTS and npm
- MongoDB (local or MongoDB Atlas)

### Backend

```bash
cd backend
npm install
# copy env.example to .env and fill in DATABASE_URL + JWT_SECRET
npm run prisma:generate
npm run prisma:db:push   # sync schema to MongoDB
npm run db:seed          # seed barangays, diseases, users, sample data
npm run dev              # http://localhost:5000
```

### Frontend (admin)

```bash
cd frontend
npm install
# copy env.example to .env (VITE_API_BASE_URL=http://localhost:5000/api)
npm run dev              # http://localhost:3000
```

### Forecast (public)

```bash
cd forecast
npm install
# copy env.example to .env (VITE_API_URL=http://localhost:5000)
npm run dev
```

## 📊 Data Model

Surveillance: `User`, `Barangay`, `Disease`, `Case`, `RiskReport`, `Alert`, `AuditLog`, `FeedbackThread`, `FeedbackMessage`.

EMR: `Patient` (+ `PatientIdentifier` composite), `Encounter`, `VitalSign`, `Diagnosis`, `Prescription` (+ `PrescriptionItem` composite type), `Allergy`, `Problem`, `Immunization`, `MaternalRecord`, `LabResult`. The `Case` model carries optional `patientId` / `sourceEncounterId` / `facilityId` / `autoGenerated` to trace auto-generated cases back to encounters while staying de-identified for surveillance reads.

EHR: `Facility`, `Referral`, `Consent`, `ClinicalDocument`, `TerminologyConcept`; `User` carries `facilityId` / `licenseNo` / `providerType`; `AuditLog` carries `purposeOfUse` / `facilityId` / `breakGlass`.

See `backend/prisma/schema.prisma`.
